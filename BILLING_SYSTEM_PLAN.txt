Full Billing Plan

Core Credit Model

Use:

$1 = 1,000 CA credits
default markup = 2x provider cost
user_charge_credits = ceil(provider_cost_usd * markup * 1000)

Example:

Provider cost: $0.30
User charge: $0.60
Credits deducted: 600 credits

Credit types:
- subscription_credits: monthly credits from plan, expiry configurable, recommended 90 days
- topup_credits: one-time purchased credits, recommended no expiry
- bonus_credits: admin/manual/promo credits, expiry configurable
- reserved_credits: temporarily held while API call is running

Balance should come from an append-only ledger, not only a mutable number.


Dynamic Billing Engine

Do not hardcode prices inside feature code.

Every paid action must use:

quoteActionCost(action, payload)
reserveCredits(userId, quote)
settleCredits(reservationId, actualUsage)

Feature code only declares what it wants to do. Billing engine decides the credit cost.

If we add a new video model, change Apify actor, replace Apify, or add a new provider later, we update backend Rate Cards / provider mappings, and all frontend button prices plus backend charges update automatically.

If a paid action has no billing config, production should block it:

No billing rate configured for this action.
Please contact admin.

Quote -> Reserve -> Settle Flow

Every paid API action follows this:

1. Quote
   - estimate provider cost
   - show credits to user

2. Reserve
   - reserve maximum possible credits before API call

3. Provider call
   - call Kie / Apify / Upload-Post / other provider

4. Settle
   - charge actual cost where available
   - release unused credits
   - refund if provider did not charge
   - follow admin refund policy if provider charged but output failed

5. Log
   - save prompt, provider, model, task ID, estimated cost, actual cost, final credits

Automation Billing Rules

Automation needs extra protection:

- minimum balance required before enabling automation
- max credits per automation run
- daily automation credit cap
- monthly automation credit cap
- auto-pause if balance is too low
- notify user before automation pauses
- skip run if not enough credits
- log skipped runs

Example:

This automation can spend up to 3,500 credits per run.
Monthly cap: 50,000 credits.
Current balance: 22,000 credits.


Stripe Integration

Use Stripe for:
- Monthly subscriptions
- One-time top-ups
- Customer Portal
- Invoice/payment history
- Failed-payment handling

Stripe webhook events:
- checkout.session.completed
- invoice.paid
- invoice.payment_failed
- customer.subscription.updated
- customer.subscription.deleted
- payment_intent.succeeded
- charge.refunded

Webhook must be idempotent:
- store Stripe event ID
- never grant credits twice for the same event


Recommended Guardrails

Add these from the start:

- Never allow credit balance below zero
- Backend is source of truth
- Frontend only displays estimated cost
- Every provider call must have a billing record
- Every provider failure must be marked as charged/refunded/released
- Every admin credit edit must be logged
- Use actual provider cost when available
- Store generated media permanently in GCS
- Kie generated media may expire, so download/store our own copy
- Low-credit email notification via Brevo
- Admin gross margin report
- Admin credit liability report
- User spend limits
- Workspace/user rate limits
- Fraud/risk review for unusually high spend
- Disable automation on failed payment
- Grace period for subscription renewal failure


Implementation Phases

Phase 1: Billing foundation
Build ledger, rate cards, provider mappings, quote API, balance calculation, and admin manual credit adjustment. No Stripe yet.

Phase 2: Frontend credit display
Add credit labels to all paid buttons. Add insufficient balance state, reserved state, and buy-credit CTA.

Phase 3: Metering enforcement
Backend blocks all paid API calls unless quote exists, balance is enough, and reservation succeeds.

Phase 4: Meter Create Content first
Apply full billing to image/video/text generation first because this is the highest-cost flow.

Phase 5: Meter Research, Persona, Social Audit
Add billing to Apify and GPT-assisted flows.

Phase 6: Meter Automation
Add max-per-run, monthly cap, low-balance pause, run logs, and skipped-run handling.

Phase 7: User Billing tab
Show balance, usage, plans, top-ups, invoices, and portal button.

Phase 8: Admin Billing UI
Build Billing Plans, Credit Packages, Rate Cards, Provider Mapping, Stripe Settings, Credit Ledger, User Billing, Billing Rules.

Phase 9: Provider pricing sync
Start with Kie. Then Apify hybrid sync/manual. Add pricing change alerts.

Phase 10: Stripe test mode
Implement Checkout, webhooks, subscriptions, top-ups, Customer Portal, and test cards.

Phase 11: Stripe production
Deploy production keys. Test $20 subscription, $5 top-up, upgrade, cancel, failed payment, duplicate webhook protection.

Phase 12: Reporting and finance audit
Add revenue, provider cost, gross margin, credit liability, refund, and automation spend reports.


Recommended Build Order

I would build it this way:

1. Ledger + rate cards + quote API
2. Manual admin credit adjustment
3. Create Content credit charging
4. Button credit display
5. User Billing tab
6. Research/Persona/Social Audit charging
7. Automation charging
8. Admin billing management
9. Stripe test mode
10. Stripe production

This keeps the risk controlled and avoids touching billing, Stripe, automation, and all paid providers at once.
